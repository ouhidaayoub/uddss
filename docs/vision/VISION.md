# Vision

This project started as a multidisciplinary project, proposed by the head of the Computer Science Department. At first I honestly looked at it like any other university project - something you finish, defend, get a grade for, and then forget about. But after thinking about it for a while, I decided to treat it differently.

Instead of just building something to get a grade, I want to use this project to actually learn what it means to build a software system from start to finish. Not just the coding part - the whole process.

The system is being built for the Computer Science Department at the University of Mohamed El Bachir El Ibrahimi - Bordj Bou Arreridj. The idea is to take official departmental data and turn it into reliable indicators, statistics, charts, dashboards, reports, and insights - things that help staff understand where the department stands, see how it's changing over time, spot trends, and make decisions based on real evidence instead of guessing.

Based on the initial project proposal, the system needs to cover student populations, academic progression, administrative situations, graduation statistics, and dashboards for decision-support. That's the foundation. More features can be added later, but they should never go against these original goals.

Honestly, the statistics themselves don't interest me the most. What I really want is everything around them - how a real system gets analyzed, planned, designed, documented, implemented, tested, deployed, and evolved. Most student projects mostly just focus on producing a working application. For this project, I want to focus on the whole engineering process, not just the app itself.

So I'm treating this like I'm building for a real organization. The users are real people, the data is real, the constraints are real - which means the engineering decisions behind it need to be real too.

One thing that keeps coming back throughout this project is trust. The system shouldn't ever produce information based on guesses, assumptions, or manually invented values. Data should come from official sources, like PROGRES or the department's own records. Before it becomes part of the system, any imported data needs to go through proper processing, validation, and verification steps. And if the system shows a statistic, an indicator, a chart, a dashboard, or a report, there has to be a clear explanation of where that came from and how it was calculated.

What matters most to me is reliability, correctness, traceability, auditability, maintainability, and simplicity of use. I want people to actually trust the information this system gives them, and I want later versions of this project to stay understandable and easy to maintain.

I want to build this with the kind of rigor you'd expect from a real internal company system. I'm not trying to copy what big tech companies do at their scale, but I do want to bring in disciplined engineering practices wherever they actually make sense. Basically, my goal is to go further than a normal student project and actually reflect how real software gets built.

I also want this project to push me past just programming. Writing code matters, sure, but software engineering is a lot bigger than that. Through this project, I want to learn how requirements are analyzed, how architectures are designed, how systems evolve, how decisions are documented, and how software is prepared for real users.

Even if this system never actually gets used by the department, I'll still count it as a win if it makes me a better engineer. At the end of the day, if I can honestly say I approached this like an engineer and not just a programmer, then that's the whole point of this project.
